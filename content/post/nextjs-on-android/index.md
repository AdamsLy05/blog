之前这个博客是用 Hugo 在手机上做的——构建一次不到一秒，因为它是静态生成，产物就是一堆 HTML。

这次做 UVS Studio 不一样：它需要服务端（API Key 不能放前端），于是要在手机上跑一个常驻的 Node 服务。同一个环境，难度上了一个台阶。

---

## 装依赖：第一次就翻车

`npm install` 跑了 58 秒，装了 113 个包。看起来正常。

但上一次失败了，报的是 `ENOTEMPTY: directory not empty`——删不掉旧目录。原因是之前有个后台进程还在写 `node_modules`，两个进程打架。

更麻烦的是，删都删不干净：

```sh
rm -rf node_modules
# rm: cannot remove 'node_modules/next/dist/server': Directory not empty
```

在 proot 环境里（用 `--link2symlink` 做硬链接模拟），普通 `rm -rf` 会卡在这种"删了又像没删"的状态。最后的解法是：

```sh
find node_modules -depth -delete
```

`-depth` 让子文件先删，父目录最后删，绕开了链接计数的问题。

这条经验值钱——**在手机上开发，失败往往不是代码问题，是环境问题**。

---

## 构建：能用，但慢

| 项目 | 耗时/体积 |
|---|---|
| `npm install` | 58 秒，339 MB |
| `next build` | 约 40 秒，62 MB |
| `tsc --noEmit` | 约 15 秒 |

能跑，但每次改动都要等。手机上做前端，最大的成本不是算力，是**反馈延迟**——你改一行样式，想看一眼效果，得先等构建。

---

## 服务要常驻，这是新问题

静态站不需要"服务"，文件在那儿就能看。Next 不行，得有个进程一直跑着。

手机上这意味着：

- 浏览器打开 `http://127.0.0.1:3000` 才能用
- **清掉 DSH 的后台，服务就没了**
- 手机重启，一切从头

解决方式是写了个小插件：输入框上方加一个「启动 UVS」胶囊，点一下拉起服务。总比每次手动敲命令强。

顺带发现，服务监听的是所有网卡，所以**同一个 WiFi 下别的设备也能访问**（用手机的内网 IP:3000）。这让它勉强算个"局域网可用"的服务。

## 那些"本来应该很简单"的坑

**一、子路径。**

站点如果挂在 `/blog/` 这种子路径下，所有绝对路径的资源都会 404。CSS 加载不出来的时候，页面长得像"主题不适配手机"，其实是样式表根本没加载。

**二、缓存。**

改了代码，手机上一看没变化，先怀疑缓存。加个 `?v=2` 再判断。

**三、LibreOffice 跑不起来。**

想转换一个 `.doc` 文件，装了 LibreOffice，结果转换命令直接失败：

```
ERROR: /proc not mounted - LibreOffice is unlikely to work well
```

`--version` 能跑，但一转换就静默退出。proot 环境下它对 `/proc` 的依赖没法满足。

最后的替代方案不是找更好的工具，而是**换思路**：用代码直接生成文档，绕开转换。

---

## 现在这个工具长什么样

一个能在手机上跑的 Next.js 应用：

- 前端：React 19 + Tailwind，四个页面
- 后端：两个 API 路由，调用 DeepSeek
- 数据：历史记录存在浏览器 IndexedDB，服务端不存任何东西
- 部署：本机 `next start`，靠插件一键拉起

它不是玩具——真的在用，每天解析几条创意。但它也确实**只适合一个人、一台设备**。

---

## 一点判断

手机能不能当开发机？

**能，但要有心理准备：你花在环境上的时间会超过花在代码上的时间。**

静态站是个甜蜜点——构建快、无需常驻、随便托管。一旦需要服务端、需要数据库、需要守护进程，手机就开始吃力了。

我现在的结论是：**手机适合"做完就走"的项目，不适合"一直挂着"的项目。** 后者还是交给一台真正的服务器。
